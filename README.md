# ПР №2 — этап 2. Прямые зависимости

Конфигурационное управление, вариант 16.
Получение прямых зависимостей заданной версии Python-пакета.
Метаданные читаются из PyPI JSON API без pip и сторонних библиотек.

## Запуск

Нужен Python 3.10+. Только стандартная библиотека, сборка не нужна.
Из папки проекта:

```sh
./run.sh --package requests --version 2.32.3
```

Прямой запуск: `python3 -B src/__main__.py` с теми же параметрами.
На Windows: `py -B -m src`. Справка: `./run.sh --help`.

## Настройки

| Параметр | Назначение |
| --- | --- |
| `--package NAME` | Имя пакета, обязательно |
| `--version VERSION` | Версия корневого пакета, обязательно |
| `--repository URL/PATH` | URL PyPI JSON API или тестовый JSON |
| `--test` | Использовать локальный тестовый репозиторий |
| `--ascii-tree` | Дополнительно вывести ASCII-дерево на этапе 5 |
| `--stage N` | Выбрать этап 1–2; по умолчанию 2 |

Репозиторий по умолчанию — `https://pypi.org`.
Настройки передаются при запуске, отдельного окна ввода нет.
Тестовый граф появится на этапе 3, ASCII-дерево — на этапе 5.

## Примеры для защиты

```sh
./run.sh --package flask --version 3.0.3
./run.sh --package rich --version 13.9.4
./run.sh --package requests --version 99999
```

Программа выводит активные прямые зависимости и ограничения версий.
Например, у `requests==2.32.3` их четыре: charset-normalizer, idna,
urllib3 и certifi. Последний пример покажет ошибку отсутствующей версии.
Учитываются условия текущего Python/ОС; неактивные extras пропускаются.
Ошибки сети, HTTP, JSON и несовместимого Python выводятся явно.

## Проверка

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты работают без сети. Примеры с PyPI требуют подключения к интернету.

## Исходники

`repository.py`: PyPI; `requirements.py`, `markers.py`, `versions.py`:
разбор зависимостей и условий; `config.py`, `cli.py`: настройки и вывод.
Точка входа — `src/__main__.py`. Исходники находятся в `src/`, тесты — в `tests/`.
