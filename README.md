# Эмулятор оболочки — вариант 16

Практическая работа № 1 по конфигурационному управлению.
Реализованы этапы 1 (REPL) и 2 (конфигурация).
Интерфейс — окно на Python и tkinter с вводом команд и историей диалога.

## Запуск

Нужен Python 3.10 или новее с поддержкой tkinter (Tcl/Tk).
Сторонние пакеты Python не используются; отдельная сборка не требуется.
Все примеры выполняются из папки проекта (`PR_1` в архиве,
корень отдельного GitHub-репозитория).

```sh
./run.sh
```

Если на Mac установлено несколько Python, укажите нужный интерпретатор:

```sh
PYTHON=/opt/homebrew/bin/python3 ./run.sh
```

Прямой запуск: `python3 -B -m src`.
На Windows: `py -B -m src`.
Также можно открыть `src/__main__.py` в VS Code и нажать кнопку ▶
«Запустить файл Python». Прямой запуск поддерживается:

```sh
python3 -B src/__main__.py
```

Проверить tkinter можно командой `python3 -m tkinter` — откроется тестовое окно.

## Параметры запуска (этап 2)

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `--vfs PATH` | Физический путь к ZIP с VFS | Не задан |
| `--startup PATH` | Путь к текстовому стартовому скрипту | Не задан |
| `--help` | Справка по запуску | — |

Параметры независимы: можно передать оба, только один или ни одного.
При запуске все заданные значения выводятся в терминал и в историю окна.
Без `--vfs` имя VFS — `MyVFS`, иначе используется имя указанного файла.
Оно отображается в заголовке окна и приглашении ввода.

```sh
./run.sh --vfs "data/Моя VFS.zip" --startup scripts/success.txt
./run.sh --vfs data/demo.zip
./run.sh --startup scripts/success.txt
./run.sh --help
```

Через Python параметры передаются так же:

```sh
python3 -B -m src --vfs data/demo.zip --startup scripts/success.txt
```

Пути с пробелами заключайте в кавычки. Неизвестный параметр или параметр
без значения выводит сообщение об ошибке и завершает запуск с кодом 2.
Справка и ошибки аргументов обрабатываются до загрузки GUI.

На этапе 2 путь VFS только сохраняется и отображается: ZIP ещё не читается
и не обязан существовать. Загрузка VFS появится на этапе 3.
Для демонстрационных сценариев создавать ZIP не нужно.

`run.sh` переходит в папку проекта, поэтому относительные пути
к VFS и скрипту при таком запуске отсчитываются от неё.
При прямом вызове Python пути отсчитываются от текущей рабочей директории.
Можно также использовать абсолютные пути.

## Стартовый скрипт

Это обычный текстовый файл в UTF-8 (допускается BOM).
Каждая непустая строка содержит одну команду эмулятора.
Пустые строки пропускаются; комментарии на этом этапе не поддерживаются.
Команды скрипта разбираются тем же парсером, что и ручной ввод.

```text
ls
ls documents "Мои документы"
cd "Мои документы"
```

После открытия окна скрипт выполняется автоматически.
История показывает введённую команду с приглашением, затем её результат.
При первой ошибке появляется имя скрипта и номер строки; следующие строки
не выполняются. После ошибки можно продолжить ввод вручную.
Если файл не найден, это каталог или кодировка неверна, выводится ошибка
чтения скрипта; окно остаётся открытым.

Успешное завершение скрипта возвращает к интерактивному вводу.
Команда `exit` закрывает окно и прекращает исполнение следующих строк.

## Команды и интерактивный ввод

Команда выполняется по Enter или кнопке «Выполнить».
Историю можно прокручивать и копировать; редактирование отключено.
Парсер понимает одинарные и двойные кавычки, экранирование и пустые
аргументы в кавычках. Пустой ввод игнорируется.

| Команда | Поведение на этапах 1–2 |
| --- | --- |
| `ls [пути…]` | Печатает имя команды и список аргументов |
| `cd [путь]` | Печатает имя и аргументы; максимум один аргумент |
| `exit` | Закрывает окно; аргументы запрещены |

`ls` и `cd` пока являются заглушками. Например, `cd "Мои документы"` выдаёт:

```text
Команда: cd
Аргументы: ["Мои документы"]
```

Они не читают файлы и не меняют текущую папку.
Неизвестные команды, незакрытые кавычки, оборванное экранирование
и неверное число аргументов выводят ошибку, после которой можно продолжить
ручной ввод. Реальные команды операционной системы не запускаются.

## Скрипты реальной ОС для защиты

Это `.sh`-файлы, которые запускают эмулятор с параметрами.
Файлы `.txt` содержат команды самого эмулятора.

| Запуск из папки проекта | Что проверить |
| --- | --- |
| `./scripts/demo_success.sh` | Оба пути, пробелы в имени VFS, вывод параметров, команды и кавычки |
| `./scripts/demo_error.sh` | Остановка на ошибке `cd one two` в строке 2; следующая команда не выводится |
| `./scripts/demo_missing.sh` | Ошибка чтения отсутствующего стартового скрипта |
| `./scripts/demo_exit.sh` | Выполнение `ls`, затем `exit`; окно закрывается |

Каждый сценарий передаёт и `--vfs`, и `--startup`.
Если нужно выбрать Python, переменная действует и для этих сценариев:

```sh
PYTHON=/opt/homebrew/bin/python3 ./scripts/demo_success.sh
```

Для защиты второго этапа покажите успешный сценарий, остановку на ошибке
и отсутствие выполнения следующей команды, затем ошибку чтения файла.
После ошибки введите `ls` вручную: окно должно продолжить работу.
Покажите также запуск без параметров, с одним параметром и справку.

Для проверки первого этапа вручную введите:

```text
ls
cd "Мои документы"
cd 'Мои документы'
abracadabra
cd one two
cd "незакрытая кавычка
exit now
ls
exit
```

## Проверки

```sh
python3 -B -m unittest discover -s tests -v
```

27 проверок покрывают парсер, команды, параметры, диалог стартового скрипта,
остановку на ошибках и `exit`, пустые строки, BOM, номера строк, ошибки
чтения, передачу параметров через `run.sh`, прямой запуск `__main__.py`
и запуск из другого каталога.
Эти проверки не открывают окно; GUI проверяется сценариями выше.

## Устройство проекта

- `src/config.py`: `Config` хранит настройки и формирует имя VFS;
  `describe` выводит параметры; `parse_config` разбирает аргументы запуска.
- `src/shell.py`: `parse_command` разбирает команду,
  `execute_command` выполняет её; `CommandError` обозначает ошибку ввода,
  `CommandResult` содержит вывод и признак завершения.
- `src/startup.py`: `run_startup` читает и выполняет скрипт;
  `StartupResult` сообщает об ошибке или запросе завершения приложения.
- `src/gui.py`: `ShellWindow` создаёт окно, записывает историю,
  обрабатывает ручной ввод и запуск скрипта; `main` запускает GUI.
- `src/__main__.py`: точка входа, разбор параметров и запуск окна.
- `scripts/`: стартовые скрипты и сценарии запуска для macOS/Linux.
- `tests/`: проверки команд, конфигурации и скрипта запуска.
- `run.sh`: запуск с передачей всех аргументов в Python.

## История этапов

Первый этап сохранён отдельным коммитом с графическим REPL.
Второй этап добавляет конфигурацию и стартовые скрипты отдельным коммитом.
Для сдачи используется публичный репозиторий с историей разработки.
