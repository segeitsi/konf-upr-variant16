# Этап 3. Виртуальная файловая система

Конфигурационное управление, ПР № 1, вариант 16. Этапы 1–3 выполнены.
Python 3.10+ с tkinter; сторонние пакеты и сборка не нужны.

## Запуск

Из папки проекта:

```sh
python3 -B scripts/generate_vfs.py data
python3 -B src/__main__.py --vfs data/nested.zip --startup scripts/stage3.txt
```

На этом Mac можно использовать `.venv/bin/python` или
`/opt/homebrew/bin/python3`. Для кнопки ▶ выберите Python с tkinter.
Параметры `--vfs`, `--startup`, `--help` вводятся в обычном терминале,
при запуске программы. Пути необязательны; настройки выводятся в окно.

## Возможности

ZIP читается без распаковки. Все узлы хранятся в памяти,
содержимое файлов представлено в base64. Архив на диске не меняется.
Загрузка обрабатывает отсутствующий файл, повреждённый ZIP,
конфликты файлов и каталогов, недопустимые пути.
Без `--vfs` создаётся пустая VFS с именем `MyVFS`.

В окне вводятся `ls`, `cd` и `exit`. На этом этапе `ls` и `cd`
ещё выводят имя и аргументы. Кавычки сохраняют пробелы в путях.
Стартовый файл UTF-8 содержит одну команду на строку; пустые строки
пропускаются. Показываются ввод и вывод; первая ошибка останавливает
скрипт, ручной ввод остаётся доступным. `exit` закрывает приложение.

## Проверка и защита

```sh
PYTHON=/opt/homebrew/bin/python3 ./scripts/demo_vfs.sh
PYTHON=/opt/homebrew/bin/python3 ./scripts/demo_vfs_errors.sh
python3 -B -m unittest discover -s tests -v
```

Первый сценарий создаёт и загружает минимальный ZIP, ZIP с несколькими
файлами и дерево глубиной три уровня. Второй проверяет ошибки загрузки.
Тестовые ZIP генерируются локально и не добавляются в Git.

## Исходники

`vfs.py`: `VirtualFS.load` загружает ZIP, `resolve` разбирает пути,
`children` возвращает содержимое каталога, `text` читает UTF-8 файл.
`config.py` разбирает параметры; `shell.py` разбирает команды;
`startup.py` выполняет скрипт; `gui.py` содержит окно.
Точка входа: `src/__main__.py`; скрипт запуска: `run.sh`.
